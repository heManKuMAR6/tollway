# ADR-0003: Build tollway in Rust

- Status: accepted (replaces the original plan's "Python 3.12, FastAPI, async httpx")
- Date: 2026-10-19

## Context

tollway is a proxy on the hot path of every agent call. Its pitch is small, self-hosted and
easy to audit, with under 5 ms of added latency at p50. Comparable gateways are written in Go
(Bifrost) and Rust (agentgateway) and publish overhead numbers in microseconds. In 2026 the
Python gateway LiteLLM was hit by a PyPI supply-chain compromise. Only a Python skeleton
existed when this decision was made, so switching was cheap.

## Decision

- Rust, edition 2024, stable toolchain. The MSRV is declared in `Cargo.toml` and tested in CI.
- One crate with a library (`src/lib.rs`) and a thin binary (`src/main.rs`), so integration
  tests can drive the app without a network.
- Runtime: tokio. HTTP server: axum. Upstream client: reqwest (rustls). Config: serde plus a
  maintained YAML crate (chosen in Phase 2; `serde_yaml` is archived). Logs: tracing with
  JSON output. CLI: clap.
- Tests: `cargo test`, with wiremock for upstream mocks.
- Checks: `cargo fmt`, clippy with warnings as errors, cargo-deny for licenses and advisories,
  and cargo-llvm-cov with an 85% line-coverage gate.
- Example agents and chaos tooling may stay in Python or shell; they talk to tollway over HTTP.

## Consequences

- Low, predictable overhead. Ships as a single static binary in a small container image.
- Supply-chain exposure is checked in CI by cargo-deny.
- Slower to iterate than Python while the design is still moving. Fewer potential
  contributors.
- Releases go to GHCR and GitHub Releases as binaries; publishing to crates.io is optional.
